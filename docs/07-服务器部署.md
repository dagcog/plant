# 07 · 自有服务器部署

以下步骤适用于一台带公网域名的 Ubuntu 或 Debian 服务器。Caddy 提供静态前端与 HTTPS，把同一个域名下的 `/api/*` 交给 Node.js。PostgreSQL 和 Node.js API 只监听本机。部署服务器上的账号与种植数据保存在服务器自己的数据库中，本机开发库单独保留。 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)

## 1. 准备服务器和源码

准备 Node.js 22、npm、PostgreSQL、Caddy 和 SSH。使用系统级 Node 安装，让后端服务能直接访问 Node 可执行文件。把 `plant.example.com` 替换为自己的域名，DNS 指向服务器，开放 TCP 80 和 443。现有站点已占用这两个端口时，在现有站点入口添加对应反向代理配置。 [Node.js 下载](https://nodejs.org/en/download) · [Caddy 安装](https://caddyserver.com/docs/install#debian-ubuntu-raspbian)

在本地项目目录打包已提交源码并上传。把 `user@server` 替换为实际 SSH 登录信息。

```powershell
git archive --format=tar.gz -o windowsill.tar.gz HEAD
scp windowsill.tar.gz user@server:/tmp/
```

在服务器执行。

```bash
sudo install -d -o "$(id -un)" /opt/windowsill
tar -xzf /tmp/windowsill.tar.gz -C /opt/windowsill
cd /opt/windowsill
npm ci
npm run build
sudo install -d /var/www/windowsill
sudo cp -a dist/. /var/www/windowsill/
```

## 2. 创建数据库并执行迁移

在服务器执行 `sudo -u postgres psql`，为迁移角色和运行角色分别设置密码。

```sql
CREATE ROLE windowsill_migrator LOGIN;
\password windowsill_migrator
CREATE ROLE windowsill_app LOGIN;
\password windowsill_app
CREATE DATABASE windowsill OWNER windowsill_migrator;
\q
```

回到 `/opt/windowsill`。在终端输入迁移连接串，例如 `postgresql://windowsill_migrator:ENCODED_PASSWORD@127.0.0.1:5432/windowsill`。连接串里的特殊字符需 URL 编码。

```bash
read -rsp 'Migration DATABASE_URL: ' DATABASE_URL; echo
export DATABASE_URL
npm run db:migrate && psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f deploy/postgres-runtime.sql
unset DATABASE_URL
```

迁移自动应用 `db/` 中的编号文件，运行权限由 `deploy/postgres-runtime.sql` 分配。运行角色通过账本触发器更新余额，应用账户可按用途写入相应表。 [PostgreSQL GRANT](https://www.postgresql.org/docs/17/sql-grant.html)

## 3. 将 API 设为系统服务

创建 `/etc/windowsill.env`，将文件权限设为 `600`，并把密码与域名替换为实际值。

```dotenv
NODE_ENV=production
DATABASE_URL=postgresql://windowsill_app:ENCODED_PASSWORD@127.0.0.1:5432/windowsill
PLANT_API_HOST=127.0.0.1
PLANT_API_PORT=3001
PLANT_FRONTEND_ORIGINS=https://plant.example.com
PLANT_TRUST_LOOPBACK_PROXY=1
```

创建 `/etc/systemd/system/windowsill.service`。如果 `command -v node` 给出不同的系统安装路径，相应修改 `ExecStart`。

```ini
[Unit]
Description=Windowsill Club API
After=network.target postgresql.service

[Service]
DynamicUser=yes
WorkingDirectory=/opt/windowsill
EnvironmentFile=/etc/windowsill.env
ExecStart=/usr/bin/node /opt/windowsill/backend/start.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now windowsill
curl --fail http://127.0.0.1:3001/api/health
```

## 4. 配置 HTTPS 入口

将站点块加入 `/etc/caddy/Caddyfile`。Caddy 保留 `/api` 路径，并覆盖用于登录限速的客户端 IP 请求头。

```caddyfile
plant.example.com {
    handle /api/* {
        reverse_proxy 127.0.0.1:3001 {
            header_up X-Real-IP {remote_host}
        }
    }
    handle {
        root * /var/www/windowsill
        file_server
    }
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl --fail https://plant.example.com/api/health
```

浏览器打开 HTTPS 站点，注册后种下一盆植物，再用另一个浏览器窗口登录同一账号，确认能看到刚种的植物。API 启动失败可用 `sudo journalctl -u windowsill -n 80 --no-pager` 查看。生产会话使用 Secure Cookie，浏览器访问请使用配置的 HTTPS 域名。 [Caddy 反向代理](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) · [systemd 服务执行环境](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)

## 更新版本

先备份服务器数据库，再解压新版本源码，运行 `npm ci`、`npm run build` 和第 2 节中的迁移与授权命令。复制新的 `dist/` 后执行 `sudo systemctl restart windowsill`，再次检查 `/api/health` 和登录。服务器运行配置保存在 `/etc/windowsill.env`，与源码包分开。

从 0.3.x 更新到 0.4.0 时，外部 PostgreSQL 部署需要重新运行 `deploy/postgres-runtime.sql`，让运行角色可以更新旧窗台盆位的目录版本。本地 PGlite 在服务启动时自动迁移。升级后的窗台使用新目录，旧版后端无法读取目录版本 2；如果要回退服务，请同时使用升级前的备份。

更新到 0.5.0 时，外部 PostgreSQL 同样需要执行迁移和授权命令，运行角色才能读写新的材料库存表。已有账号和植物会保留，新版会在玩家下次访问时升级窗台内容版本。
