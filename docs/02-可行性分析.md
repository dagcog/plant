# 02 · 可行性分析

## 结论

单机浏览器试作可用一个静态站点验证完整种植循环。窗台固定相机、少量盆位和独立特写，把 3D 制作量与交互复杂度控制在小范围。账号、实时社交、跨端同步和公开内容治理需要服务端，并会改变长期维护成本。

## 技术与内容

| 领域 | 当前实现 | 可行性与代价 |
| --- | --- | --- |
| 光照与 3D 查看 | Three.js WebGL 2、方向光投影、天空画布纹理和半透明光束。OrbitControls 处理旋转与缩放。 | 真实 3D 模型能展示叶片与盆器侧面。GPU 不可用时降级为插画，种植操作继续可用。低端移动 GPU 的流畅度仍需实机测试。 |
| 植物资产 | 三种程序化形态及三种盆器，通过参数生成颜色、大小、花瓣和枝条。 | 可快速添加同形态品种。新叶型、透明材质和高细节模型需要额外的模型制作与光照验证。 |
| 成长与时钟 | 本地规则层以固定步长累计环境质量，离线时按时间戳补算。 | 同一输入和种子复现同一株植物。系统时间与本地存档可被用户修改，适合单机。联网经济需要服务端时钟与校验。 |
| 保存与分享 | `localStorage` 保存进度。花架快照以 URL 片段传输。 | 部署后可直接发送链接。快照不随源花架更新，喜欢留在本地。链接包含可读展品数据，持有链接者均可打开。 |
| 部署 | Node.js 负责开发、测试、构建和本地预览，部署只需要静态文件。 | 无数据库和运行中的业务服务。需要网络分发时，仍要配置玩家可达的托管地址。 |

使用了 Three.js 的官方安装方式和 OrbitControls 输入接口。 [Three.js 安装手册](https://threejs.org/manual/pages/installation.html) · [OrbitControls 文档](https://threejs.org/docs/pages/OrbitControls.html)

## 主要风险与验证方式

- **养护手感过于隐晦。** 比较只等待与按习性养护的品质、尺寸、分枝和价格。记录首次体验者能否自行理解光照选择，以及是否错误地反复浇水。
- **异色诱发重复刷取。** 试玩用 5%–21% 的品质相关概率。正式版测试玩家是否愿意接受普通花色，是否为稀有颜色连续重复同一操作。图鉴完成以物种为单位。
- **小屏操作与设备差异。** 浏览器验收包括窄屏、按钮键盘操作、长列表、鼠标和触屏输入路径。上线门槛另设代表性安卓机、iPhone 和低配电脑的首帧、特写交互和发热实测。
- **存档可靠性。** 测试无权限、损坏版本、刷新、多标签页和时间回拨。联网阶段再引入账号映射、历史版本迁移、事务及恢复策略。
- **邻里生态。** 先观察是否有人主动分享和回访。公开索引、留言及账号资料会增加隐私、举报、内容审核和反滥用工作，应分别确定运营归属和验收条件。

## 里程碑与范围

1. **当前试玩。** 静态版、四份设计文档、规则测试和浏览器冒烟。先验证操作、画面和轻养护节奏。
2. **内容内测。** 增加多种植物、盆器和展陈主题。根据试玩记录调整时间与反馈，并建立资产预算和旧存档夹具。
3. **联网内测。** 加入账号和云存档、花架发布与撤回、鉴权和同步喜欢。使用独立测试环境验证一致性后再开放邀请。
